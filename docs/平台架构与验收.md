# 平台架构与后续验收

## 边界

平台设计串联可重构臂。模块、接口族和装配规则是通用 schema；一条设计是模块序列、相邻接口的离散方位，以及各模块声明过的连续参数。

当前不做树、闭环、抓取策略重训，也不把未测量的硬件写成实物。

## 模块库

| id | 种类 | 接口 | 可优化参数 |
| --- | --- | --- | --- |
| `zbot_r3` | 实物 | `zbot_flange` → `zbot_flange` | 无。尺寸、质量、±6.28 rad 来自 R3 `ZBOT6.xml` |
| `concept_axial` | 概念 | 同上，因此可以插入 ZBot 链 | 长度 0.06–0.16 m。线密度 4 kg/m、胶囊半径 0.025 m 是假设 |
| `demo_unreleased` | 概念示例 | `demo_flange` | 没有与 `zbot_flange` 的装配规则，混合链会被拒绝 |

实物模式的搜索目录只有 `zbot_r3`。概念混合模式加入 `concept_axial`。

## 代码

- `src/zbot_exolimb_grasp/platform/schema.py`：模块、规则、设计、任务和搜索规格。
- `library.py`：注册表。新模块应加在这里，并声明接口族。
- `model.py`：串联 FK、平移雅可比、采样评价和约束。
- `nsga2.py` / `search.py`：约束支配 NSGA-II。违反约束的个体不进可行前沿。
- `exporting.py`：JSON 由搜索结果直接序列化；另有 CSV 和 MJCF。MJCF 用同一套体坐标解释核对末端。
- `web/src/platform/`：浏览器里的同一评价和一版 NSGA-II，跑在 Web Worker 中。

## 指标与明确不做的事

任务主指标是固定格点上的可行比例：同一组目标、同一位置容差、同一 IK 起点和迭代预算下，有多少格点找到了同时满足关节限位、胶囊无碰撞和静力矩的解。分母是格点数。没解出来只说明这个预算没找到，不是严格不可达，也不是工作空间体积。

末端落盒比例如果单独计算，是随机关节样本掉进任务盒的比例，可以包含碰撞和超力矩姿态。它的二项标准误差只描述这个关节采样，不能叫做任务覆盖率。

平移可操作度和速度能力只在上述可行任务解上取中位数。一个可行解都没有时，这两项标为无效，优化目标用有限惩罚，不把 NaN 放进前沿。全体关节样本上的中位数如果计算，会另标成全姿态描述。

零位碰撞和零位力矩只作诊断。零位不是可重构装配必须使用的工作姿态，不能据此把整条设计判成永远不可用。

没做，界面和结果里写明不支持：STL 精确碰撞、逆动力学、加速度能力、把转动雅可比和平移雅可比拼成一个分数、树和闭环。

关节速度默认 1.5 rad/s，是假设。力矩默认 20 N·m，来自仓库里的位置伺服；改掉之后记为用户覆盖。

## 后续验收

1. 第二套实物模块必须带实测质量、关节限位和接口图纸，不能复用概念密度。
2. 若要树形肩或双手，先扩展拓扑枚举和装配规则，再谈优化。
3. 速度多面体和网格碰撞只有在计算预算和几何来源都明确后才进入分数。
4. 浏览器与 Python 的随机数流目前不一致。若要求逐个体复现，应统一随机数实现，而不是调低测试精度。
